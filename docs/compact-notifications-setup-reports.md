# Compact notifications, reports and setup progress

This batch requires only the frontend deployment. No new SQL, Edge Function, secret or live database operation is included. Do not rerun earlier migrations for this batch.

## Notifications

The admin bell now opens one combined list of account announcements and the registered owner's subscription notices. Staff still receive only their authorized announcement feed. Both unread and read rows show only the title, date/time and status. A full message opens in a dedicated dialog when clicked. Opening the list alone writes no read receipts.

Full-message opening uses the existing read API for the original source: subscription notice keys go to `iv_subscription_portal/read_notice`; announcement IDs and exact revisions go to `iv_account_announcements/read`. Member announcements use their existing member feed API. No approval, payment, extension or entitlement operation is introduced. Read failures leave the message unread and expose a retry; partial feed failures show an error rather than falsely claiming all messages are read. An open full message is retained during background list refreshes; closing it renders the latest queued list. Auth changes remove private dialogs and late responses cannot restore them.

## Reports

Only the selected tab retains the active class. Legacy fixed Money highlighting is removed when switching tabs. The two-column Money layout is now:

| Left | Right |
| --- | --- |
| Membership sales | Net cash received |
| Wallet spending | Wallet top-ups |
| Refunds to wallet | Cash refunds |
| Credit corrections in | Credit corrections out |

Existing report models, formulas, filters, search, pagination, CSV/Excel and print/export code remain unchanged. Export ordering is unchanged; this request changes the screen card arrangement.

## Setup progress and editable examples

The display reads saved gym details through the existing authorized `iv_legal_manage/get` API. Gym Terms & Privacy is complete only when its required saved rows, email format and effective date are complete. Optional phone/refund/age fields do not block completion. Service Agreement completion continues to use its own accepted status. Neither step completes the other.

This adds a display-only saved-details check. The existing published-document flags, owner acceptance, provider approval, pilot duration and server activation checks are unchanged. Complete saved details that are not yet published show a reminder and Review / publish action. A successful draft save refreshes visible setup labels without accepting an agreement, publishing documents or starting a pilot. Failed reads show an unverified state, not an inferred completion.

Approved examples fill only empty gym policy fields. Existing answers are preserved, including older saved wording; it is not silently rewritten. Clean examples contain no “Suggested:” prefix. Business identity, address, emails, phone and actual effective date must still be entered by the owner. Examples remain editable and are neither saved nor published automatically. Retention wording does not schedule any automatic deletion. Owner review and the existing publication controls remain required.
