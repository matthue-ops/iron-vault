# Subscription interface update

This change uses the existing Supabase RPCs, authorization, immutable document versions, review checks and subscription calculations. No SQL migration or Edge Function deployment is required. It does not publish documents, activate pilots, approve payments or delete records during deployment.

- `assets/subscriptions.js` opens Service Agreement Settings on Documents, with separate App settings and Payment & contact tabs. Existing full-document editing, copy, save, preview, revision protection and explicit publication review remain. Existing template metadata stays in collapsed details for compatibility with the current server validator and template placeholders. The editor loads a preview immediately. Changing app settings still requires choosing whether to keep edited text or regenerate it; prose never silently changes billing.
- Provider subscription reviews hide pilot controls after pilot use, show only unresolved requests, reveal return reasons on demand and collapse extensions. Requests remain in History. Buttons show a processing indicator, block repeated clicks, retain their icons, and preserve form values on errors. Successful Provider actions refresh server status and display confirmation. Shared CSS provides dark inputs, readable cards and mobile spacing.
- `assets/legal-documents.js` groups gym retention policies and fills only blank retention fields with clearly marked suggestions. Financial and backup policies remain distinct. Suggestions are draft text; they do not automate deletion. Existing policy values are preserved. Saving incomplete drafts remains available; publication still requires preview and explicit review.
- `gym/index.html` leaves only Gym Profile in tenant row actions. `assets/gym-profile.js` adds Suspend/Reactivate beside Purge in the profile menu, reusing the existing status handler. Subscription, edit and Test/Live actions remain in the profile.

Validation: `npm test`, `npm run build:pages`, dashboard and service-policy generation checks. Browser regressions in `tests/browser/` use Playwright, Chromium at `/usr/bin/chromium`, and mocked RPC responses; run each with `node tests/browser/<filename>.cjs` from the repository root. No production database was queried or changed. Check real Provider and owner flows after deploying the branch against the existing manually installed subscription schema.
